    运行大规模计算

    中文译文 · 由本地英文文档翻译，已统一术语并进行重点抽查。 英文原文对照 · 翻译说明

    声子计算即使在小型晶体系统上，通常也需要比基态计算多出数倍的CPU资源。DFPT方法计算声子色散时，需要在多个声子波矢处求解动力矩阵，每个波矢处的动力矩阵包含若干扰动项的计算。由于扰动会破坏对称性，每个扰动通常都需要一个较大的k点集。如果采用超胞方法，则收敛计算需要典型数百原子规模的体系，并涉及大量扰动项，尽管所使用的k点集较小。因此，对于科学界感兴趣的体系而言，声子计算往往需要部门级、大学级或国家级超级计算设施，通常是并行集群类计算机。

    关于如何高效使用集群或超级计算机资源的建议，与地面态或其他类型的CASTEP计算基本相同，但声子计算有一些特殊考虑事项，如下所述。其中特别相关的一般性事项包括内存/速度之间的权衡选择；通常最佳的做法是选择最高速度选项。 opt_strategy_bias : 31 哪种方式会将波函数系数保留在内存中，而不是写入磁盘。对于大规模计算而言，通常内存需求（尤其是波函数的内存占用）是选择并行分布时最重要的考虑因素。如果由于超出每个节点可用内存而导致计算失败，则应增加请求的处理器数量，以将波函数数组分布在更多的处理器上，从而降低每处理器所需的内存。

    如果无法增加并行分布的程度，则 opt_strategy_bias 可以减少到 02，将页波函数写入磁盘。在这种情况下，必须确保临时缓存文件被写入高速磁盘（无论是本地磁盘还是高性能文件系统）。这通常通过设置环境变量来控制。 CASTEP_PAGE_TMPDIR 指向一个适当文件系统的目录3.

    并行执行

    CASTEP 实现了一种基于k点、平面波、能带以及OpenMP在处理器之间进行分层分布的并行策略。4在声子计算中，这被用来加快每个扰动和q点内的执行速度，尽管这些扰动和q点仍按顺序串行执行。通常会自动选择一种高效的分布方式，前提是 data_distribution 参数未从默认值更改 MIXED.

    k点、平面波、能带和任务农场并行性均采用以下方式实现 消息传递接口 （MPI）系统，并且通常需要通过使用可执行文件启动 CASTEP。 mpiexec 或者类似的命令，即

    mpiexec -n 1024 castep.mpi <seedname>

    这将启动 1024 个 MPI 进程，并将其分布在这些进程中。

    相比之下 OpenMP 并行性通过设置环境变量来激活 CASTEP_NUM_THREADS : <n>，这可以在计算之前完成 mpiexec 激活混合 MPI+OpenMP 模式的命令。

    k点与g矢量的平行性

    为了最好地利用k点的并行分布，请求的处理器总数应是电子k点数量的倍数，或具有较大的公约数。并行分布会打印到 .castep 文件，其中在此示例中使用了四个k点：

    Calculation parallelised over   32 nodes.
K-points are distributed over    4 groups, each containing    8 nodes.

    对于非声子 CASTEP 计算，只需选择一个是倍数的处理器数量即可。 N_{\text{k}}，且平面波平行度不至于大到导致效率降低。然而，在声子计算中选择处理器数量这一问题，由于在运行过程中，不可约布里渊区中的电子k点数目会随着扰动和声子q点的不同对称性而变化，因此变得极为复杂。单独为每个扰动计算所需数量并不方便，且需要进行详细的分析，因此应选择一个对所有扰动都相对合理的折中方案。为了辅助这一选择，提供了一个实用程序， phonon_kpoints 已提供。该功能读取所提议计算的配置信息来自 .cell 文件，并通过简单调用即可启动

    phonon_kpoints seedname

    然后它会确定并打印k点数量，并为一系列可能的处理器数量提供一个“性能指标”。在大多数并行架构中，如果每个节点的平面波数量少于约200个，则平面波并行效率将变得不可接受。通常可以选取一个处理器数量，使得运行高度并行化的同时，每个节点上的平面波数量远高于此数值。

    带平行化

    从 CASTEP 24.1 版本开始，FD 计算实现了带宽并行，但 DFPT 尚未实现。可通过在中添加“devel-code”字符串来启用此功能。 .param 文件5

    %block DEVEL_CODE
PARALLEL:NBANDS=8:ENDPARALLEL
%endblock DEVEL_CODE

    将尝试在k点和g矢量的基础上设置8路带平行化。

    扰动并行性

    从 CASTEP 24.1 版本开始，可以使用一种称为“任务农场”（task-farming）的进一步并行级别，将扰动分布到各个处理器上。该功能的设置和运行方式与 PIMD 或 NEB 计算相同，只需在参数文件中设置关键字即可。 num_farms : <n>．值为 n 不应过大，因为性能将受到负载平衡问题的限制，而且在任何情况下都不应超过扰动的数量。这将产生 n 输出文件命名为

    <seedname>_farm00<n>.castep

    而不是通常的单个 .castep 文件。其中， <seedname>_farm001.castep 将包含计算得到的最终频率、Born 有效电荷等信息，但单个实例的 .phonon, .efield, .phonon_dos 并且 .check 文件的写入方式与其他并行方案相同。

    混合 OpenMP 并行计算

    除了上述描述的基于MPI并行的并行分布策略外，CASTEP还提供了一定程度的OpenMP并行性。6这可以加快一些操作（如矩阵对角化）的速度，并通过设置环境变量来激活。 CASTEP_NUM_THREADS : <n> 其中 n 在 2 到 16 的范围内效果最佳（使用 OpenMP 只能获得有限的加速）。然而，这可以为 MPI 并行计算提供额外的性能提升，特别是在计算节点因内存需求而必须被低负载使用的情况下。

    检查点与续算

    即使使用并行计算机，也常常会出现单次运行无法完成计算的情况。许多机器对批处理队列设有最大时间限制，该限制可能过于短暂。在台式机上，运行时间可能受到可靠性和可用时间的限制。CASTEP 可以周期性地写入“检查点”文件，其中包含计算状态的完整记录，并能从这些检查点文件中重新启动并完成计算。特别是，完整的q点动力矩阵以及每次扰动对应的局部动力矩阵都会被保存下来，可用于重启计算。为了启用周期性写入检查点文件，需设置参数

    backup_interval 3600

    将会写入一个名为checkpoint文件的检查点文件 seedname.check 每小时（时间以秒为单位）或在下一个扰动计算完成后，进行重启。要重启计算，请设置该参数

    continuation : default

    在 .param 提交作业前请检查文件。这将尝试读取 seedname.check 并且可以从该位置重新开始计算。或者，可以将检查点文件的完整文件名作为参数传递给 continuation 关键词用于读取一个显式命名的文件。

    在计算结束时将生成一个检查点文件 seedname.check 始终被写入。与中间检查点文件类似，它包含（现已完整）由声子计算得出的动力学矩阵或力常数矩阵。该数据可在后续处理阶段使用进行分析。 phonons 工具。
