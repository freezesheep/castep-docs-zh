    CASTEP 构建系统

    中文译文 · 由本地英文文档翻译，已统一术语并进行重点抽查。 英文原文对照 · 翻译说明

    简介

    本文档旨在为计划向CASTEP系统添加新功能/数据源的开发者提供参考。如何构建CASTEP的快速入门指南见于 CASTEP_ROOT 在 README.INSTALL 用于 GNU Make 构建系统或 README.cmake 用于新的 CMake 构建系统。

    CASTEP 的构建系统旨在高效且易于使用。目前存在两个构建系统：一个基于 GNU Make，构建速度更快，适用于快速开发；另一个基于 CMake，对熟悉 CMake 构建系统的用户更直观，并能为普通用户提供自动检测最佳配置的功能。

    CASTEP 目录结构

    在为 CASTEP 增加新源代码时，重要的是要考虑 CASTEP 的层次目录/模块结构。目前，CASTEP 源代码被组织成若干子库，每个子库都依赖于其在层级结构中上方的库。

    这些库按照层级顺序为：

    • Utility
    • Fundamental
    • OTFG
    • Dispersion
    • Functional

    也存在 Tools 这些是分别构建的程序，依赖于 CASTEP 子库。

    GNU Make

    该 GNU make 构建系统被分解为一个层次化的树结构，以在尽可能多的异构系统上编译CASTEP时建立所需的规则，同时保持各部分的隔离性和可维护性。

    这些 Makefile 的层级结构如下：

    ├ `<CASTEP_ROOT>/`
└─┬─ `Makefile` - Root Makefile
  ├─ `obj/`
  └──┬─ `include_rules.mk`
     ├─ `include_utility.mk`
     ├─ `include_fundamental.mk`
     ├─ `include_otfg.mk`
     ├─ `include_dispersion.mk`
     ├─ `include_functional.mk`
     ├─ `include_test.mk`
     ├─ `include_tools.mk`
     ├─ `platforms/`
     └──── Various make rules for different platforms

    CMake

    该 CMake 系统旨在对熟悉 CMake 构建系统的用户具有直观性，同时对熟悉 CASTEP GNU Make 语法的用户仍保持亲切感。这意味着许多 CASTEP CMake 变量的命名被选择以匹配或别名为 CASTEP GNU Make 变量。此举旨在减少从 GNU Make 迁移到 CMake 的用户产生困惑的情况。

    CMake 系统也旨在扩展 CASTEP 的功能，使其能够高效地在 Windows 系统上进行编译和运行。

    添加新源文件

    为了向CASTEP中添加新的源代码，首先需要确定相关的依赖关系，并明确它们在目录结构中的位置（即CASTEP的子库）。

    添加到 GNU Make 构建系统

    随后应将该源添加到相关 obj/include_<sub_library>.mk SRCS_$(D)这将自动将您的新源包含在 CASTEP 子库中。

    添加到 CMake 构建系统

    下一步是进入包含您新源文件的子库文件夹，并将源文件添加到其中。 CMakeLists.txt 其中。

    条件包含

    如果源文件提供了应在CASTEP中条件性包含的函数（例如对外部库的接口），则该文件必须提供占位函数（通常） no-op以便条件包含可以被编译，这些内容通常会被保存为 source_name.stub.f90 并且这些必须有条件地包含在编译中。

    添加到 GNU Make 构建系统

    首先，重要的是在相关部分添加一个条件语句。 obj/include_<sub_library>.mk 以包含你的 stub 或主源文件进入编译过程。

    obj/include_<sub_library>.mk 

    ifeq (${MY_LIBRARY_VAR},none)
SRCS_$(d) := $(SRCS_$(d)) source_name.stub.f90
else
SRCS_$(d) := $(SRCS_$(d)) source_name.f90
endif

    如果需要有条件地链接额外库，则应按如下方式添加： obj/include_rules.mk 

    ifneq (${MY_LIBRARY_VAR},none)
  ifneq ($(strip $(MY_LIB_REL_LIB_DIR)), )
    CASTEP_LIB_SEARCH_PATH += -L"../$(MY_LIB_REL_LIB_DIR)"
  ifdef SUN
    CASTEP_LIB_SEARCH_PATH += -R "$(abspath ../$(MY_LIB_REL_LIB_DIR))"
  else ifdef NAG
    CASTEP_LIB_SEARCH_PATH += -Wl,-Wl,,-rpath="$(abspath ../$(MY_LIB_REL_LIB_DIR))"
  else ifdef LINUX
    CASTEP_LIB_SEARCH_PATH += -Wl,-rpath="$(abspath ../$(MY_LIB_REL_LIB_DIR))"
  endif
  LIBS += -lmy_extra_lib
endif

    添加到 CMake 构建系统

    使用 CMake 的过程类似，创建一个变量以根据选项选择源代码或占位符。

    e.g. CASTEP_ROOT/CMakeLists.txt 

    option(WITH_MY_LIB "my lib's features")

    cmake/extralibs.cmake 

    if(WITH_MY_LIB)
    set(MY_LIB_MOD source_name.f90)
else()
    set(MY_LIB_MOD source_name.stub.f90)
endif()

    SOURCE_DIR/CMakeLists.txt 

    add_castep_lib(NAME sub_lib
   SRCS
   ...
   ${MY_LIB_MOD}
   ...
   )

    如果需要有条件地链接额外库，则应按如下方式添加： cmake/extralibs.cmake 

    if(WITH_MY_LIB)
  find_library(my_extra_lib NAMES my_extra_lib
               HINTS ${EXTERNAL_MY_LIB}
               DOC "Doc")

  if (NOT my_extra_lib)
    message(FATAL_ERROR "MY_EXTRA_LIB requested, but not found.
Set EXTERNAL_MY_LIB to manually specify location of libraries (currently: '${EXTERNAL_MY_LIB}')")
  endif()

  set(MY_EXTRA_LIB ${my_extra_lib})
  set(MY_LIB_MOD source_name.f90)
else()
  set(MY_EXTRA_LIB "")
  set(MY_LIB_MOD source_name.stub.f90)
endif()

...

mark_as_advanced(... my_extra_lib)

    SOURCE_DIR/CMakeLists.txt 

    target_link_libraries(sub-lib ... ${MY_EXTRA_LIB})

    特殊编译选项

    如果需要为每个文件添加特殊编译选项，首先应确保您的代码符合标准规范。若无法满足此要求，则可以通过在各个平台中设置选项来覆盖默认设置，但这种情况除非绝对必要，否则不建议这样做。

    添加到 GNU Make 构建系统

    在 GNU make 系统中，需要在每个相关的平台下添加特殊的编译标志，以置于 obj/platforms 目录。例如

    obj/platforms/<platform>.mk 

    <source_file>.o: private OPT = -O2

    添加到 CMake 构建系统

    在 CMake 构建系统中，标志在的 cmake/buildflags_<platform>.cmake 文件。要覆盖标志，该 set_special_flags 已定义一个函数，用于覆盖特定构建优化的标志。

    set_special_flags(OPT FAST FILES <source_file>.f90 FLAGS -O2)
