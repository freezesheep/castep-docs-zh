    使用 trace 模块

    中文译文 · 由本地英文文档翻译，已统一术语并进行重点抽查。 英文原文对照 · 翻译说明

    该 trace 该模块提供了对castep特定部分进行调试和性能分析时对开发者有用的函数。通常的做法是在代码中插入调用 trace_entry 并且 trace_exit 在 CASTEP 程序的函数调用开始和结束时，但其中原因可能并不明确。

    大多数用户的主要原因是当 CASTEP 执行一个 io_abort，它首先调用进入 trace 在每个过程中将当前调用栈转储到 <seedname>.<process_id>.err 文件。这是人们在CASTEP计算失败时看到的主要错误信息。

    本文旨在更详细地说明CASTEP计算材料学软件的使用方法。 trace 模块及其如何以及为何对开发者有益。

    该 trace 模块

    追踪代码

    追踪块

    该 trace 模块提供了若干在调试和性能分析代码时有用的函数。关键函数在 trace 用于一般用途的是 trace_entry 并且 trace_exit 这应用于所有主要功能中。这使得子程序在追踪时被记录。

    说明

    该 trace_entry 并且 trace_exit 这些例程都有相应的开销，因此对于被频繁调用的短例程（例如循环中的函数），为它们进行跟踪可能会对性能产生不利影响。

    CASTEP 的语法为 trace_entry 是：

    call trace_entry(block_name, success[, profile][, class])
    其中：

    • block_name - character, intent(in) — 是跟踪条目中的名称。
    • success - integer, intent(out) - 是函数的返回状态， 0 如果成功的话。
    • profile - logical, intent(in) - 是否对本块进行分析 profiling
    • class - character, intent(in) — 是用于目的的配置类 profclass 实现剖面分析。

    CASTEP 的语法为 trace_exit 是： 

    call trace_exit(block_name, success)

    其中：

    • block_name - character, intent(in) — 是跟踪条目中的名称。
    • success - integer, intent(out) - 是函数的返回状态， 0 如果成功的话。

    说明

    trace_entry 并且 trace_exit 子程序可以在任意代码块周围被调用。这不仅使得可以定位失败点，还可以用于分析性能未达预期的代码部分。

    轨迹截面

    可以将代码中的某一部分标记为追踪块的子元素，而不是作为一个独立的块。这些子元素还可以在特定阶段传递额外的参数给日志参数。

    CASTEP 的语法为 trace_section 是：

    call trace_section_entry(section_name[, variable_name, value], success[, class])
    其中：

    • section_name - character, intent(in) — 是跟踪条目中的名称。
    • variable_name - character, intent(in) - 是要附加到跟踪输出部分的日志名称
    • value - integer|character, intent(in) - 是待记录变量的当前值。 value 可以是任意一种 integer 或者 character(len=63)
    • success - integer, intent(out) - 是函数的返回状态， 0 如果成功的话。
    • class - character, intent(in) — 是用于目的的配置类 profclass 实现剖面分析。

    CASTEP 的语法为 trace_exit 是：

    call trace_section_exit(block_name, success)

    其中：

    • block_name - character, intent(in) — 是跟踪条目中的名称。
    • success - integer, intent(out) - 是函数的返回状态， 0 如果成功的话。

    调试

    踪迹堆栈由以下部分构成 trace_entry 并且 trace_exit 一些用于跟踪代码当前执行位置的子程序。这就是为什么建议所有主要子程序（如上注释所述，尽可能地）以某特定方式开始和结束。 trace_entry, trace_exit.

    追踪也可以用于将信息输出到一个 日志文件 每当一个 trace_entry/trace_exit 调用 is hit。这是通过以下方式实现的：

    call trace_set_debug(.true.)

    然后可以在模块内通过以下方式检查是否启用了跟踪调试：

    if (trace_debug_is_on()) then
   ...
end if

    性能分析

    Trace 也提供了性能分析功能，用于测量任意两个时间点之间的持续时间。 entry & exit. 时间控制可通过设置相关参数实现 prof 或者 profclass 开发代码以启用（见：下文).

    也可以通过以下方式全局启用性能分析：

    class trace_set_profile(.true.)

    随后以类似方式禁用它：

    class trace_set_profile(.false.)

    该 trace 模块跟踪多个有用的性能指标，包括函数执行时间、调用次数以及每次调用所花费的时间。

    开发代码

    该 trace 该模块包含若干功能，可通过开发代码启用。

    全局
    • FULL_TRACE - logical - 启用所有模块的完整性能分析，包括 trace 模块本身。
    • TRACE - logical - 启用将函数调用自动写入性能分析文件的功能
    PROF 块

    为 CASTEP 提供时序控制。

    # Prints profiling information for the whole run
# i.e. how long is spent in each subroutine.
%block devel_code
PROF: * :ENDPROF
%endblock devel_code
    PROFCLASS 块

    需要匹配的“类别”列表（参见：） trace_entry)，以支持特定操作组的性能分析。

    %block devel_code
PROFCLASS:FFT ORTHOGONALISATION:ENDPROFCLASS
%endblock devel_code

    将打印出在带有特定类标签的例程中所花费的总时间的表格。

    这将产生如下输出： 

    Class of operation                  Time spent
FFT                                     1.41s
ORTHOGONALISATION                       0.05s

    说明

    对于 PROF:<stuff>:ENDPROF 并且 PROFCLASS:<stuff>:ENDPROFCLASS 那里必须不能有空格在 devel_code 在冒号（:）字符之前或之后，即 PROF:wave:ENDPROF 并且不是 PROF: wave :ENDPROF

    导出信息

    可以随时导出追踪信息。为了获取包括时间戳、函数调用等全部信息，您可以调用 trace_output 如下：

    call trace_output(out_unit, success, order)

    其中：

    • out_unit - integer, intent(in) - Fortran 文件单元用于写入
    • success - integer, intent(out) - 是函数的返回状态， 0 如果成功的话。

    • order - character, intent(in) - 用于输出跟踪信息的顺序，必须是以下之一：

      • L — 他们被（首先）添加以进行追踪。
      • T - 函数中总耗时的降序排列。
      • C - 调用次数的降序排列。
      • P - 按每次调用所耗时间从大到小排序。

    也可以快速导出当前的调用栈。具体操作如下：

    call trace_log_output(out_unit, success)

    其中：

    • out_unit - integer, intent(in) - Fortran 文件单元用于写入
    • success - integer, intent(out) - 是函数的返回状态， 0 如果成功的话。

    输出格式

    如果其中任何一个 TRACE, FULL_TRACE 或者 PROF devel_codes 存在时，或调用时 trace_output，CASTEP 写出一个调用每个子程序的表格（类似于以下格式）：

    +------------------------------------------------------------
| o-- list of parent routines
|  /
| O->name of subroutine
|  /
| --o-> list of child routines
+------------------------------------------------------------

    父级例程列表中包含有关该父级例程调用当前例程次数的信息。

    所关注的子程序中有关于它总共被调用次数的信息。

    子例程列表中包含某个特定子例程被感兴趣子程序调用的次数。

    如果启用了性能分析，对于所有或部分的子程序，将多出一列用于显示该子程序被调用的次数以及每个子程序所花费的总时间。

    日志文件

    默认情况下，CASTEP 会创建 <seedname>.<process_id>.profile 文件用于记录跟踪信息。
